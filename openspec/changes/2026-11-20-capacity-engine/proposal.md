# Proposal

## Why

「智能辅助决策」问「以现有资源最多能生产多少把 71-75」时跑偏：模型没有「可产数量」工具，只能硬套最接近的 `query_gap`，用「成品计划 707 − 活动齿块缺口 610 = 97」硬凑出错误答案（单位都不对：把数减件数），瓶颈件也找错（答「活动齿块」，实为「自由钳外管」）。

根因是**能力缺失**：agent 工具层只有「库存 / 缺口 / 完成率」三个只读工具，缺一个「现有资源可产数量」的确定性工具。模型被提示词逼着「数据问题必须调工具、严禁反问」，无工具可用只能硬凑。

## What Changes

- **ADDED `agent-core` 产能查询工具 `query_capacity`**：用确定性代码计算「现有资源可产数量」，返回「可产把数 + 瓶颈件 + 两维明细」，替代模型硬凑。
- **产能计算口径（两维，2026-11-20 业务方口述锁定）**：
  - 第一维度（装配）：1 把 = 1 组装简易钳体(装配I) + 1 活动齿块(半成品H) + 1 自由钳外管(半成品H)，取 min。
  - 第二维度（组装追加，触发 = 齿块和外管都有剩余）：1 简易钳体 = 2 固定钢板(毛坯C) + 1 活动钳体(H) + 1 夹紧头(H) + 2 长销子(H) + 1 短销子(H) + 2 组装齿块+方块座(H)，floor(min(现有量÷用量))，追加 = min(可新组, 剩余齿块, 剩余外管)。
- **统一产能引擎 + 配置驱动**：产能计算逻辑抽成通用引擎，BOM（第一/第二维度配件及用量）下沉为品类配置；`capacity.py` 现有实现改造为配置驱动骨架（为阶段 2 多品类复用铺路）。
- 复用既有确定性数据读取 `gap_stat.extract_gap_stat`，不重写排产结果解析。

## 本次范围边界（阶段 1）

- **本次做**：钻杆钳**两个独立规格** 54-56、71-75 的产能计算 + `query_capacity` 工具 + 配置驱动骨架 + 提示词止血（禁止拿缺口硬凑可产数）。
- **本次不做（阶段 2 及后续）**：
  - 借件规格 89-95、114-117（齿块/外管「见71-75」，与 71-75 共享库存，需竞争分配）；
  - 借用规格（成品计划 = 0：139-146 / 86-91 / 58-62 / 108-110，不单独排产）；
  - 其他品类（加力 / 美式 J/K / 内管钳 / 套管钳）——加力钳已有独立 `MRP加力` 脚本，后续统一；
  - 跨品类借用（内管钳/套管钳借钻杆钳外管）、组合件蕴含、外管焊接、毛坯规则、顺序贪婪竞争口径（阶段 2 复用加力钳已验证逻辑）。

## Capabilities

### Modified Capabilities

- `agent-core`：新增「产能查询工具」requirement（ADDED）。

## Impact

- **数据源**：`data/raw/半成品生产计划V2.0.xlsx`（与 `query_gap` 同一份，读 C/H/I 现有量）。
- **依赖既有能力**：`semi-finished-planning`（`gap_stat.extract_gap_stat` 提取，已 0 差异验证）。
- **性能**：单规格 `calc_capacity` 实测 ≤200ms；全规格循环只读一次文件，已从 1258ms 优化到 ~132ms（≤200ms 约束）。
- **真值锚点**：54-56 = 210（瓶颈=组装简易钳体）、71-75 = 627（瓶颈=自由钳外管），来自真实台账快照，非自设输入。
- **不引入**：新数据源、新第三方依赖。
