# Spec Delta

## Purpose

定义驾驶舱作为 Web 应用的整体运行约束与模块承载边界，明确本次范围内各功能模块的归属关系。

## ADDED Requirements

### Requirement: Web 应用形态
驾驶舱系统 SHALL 以 Web 应用形态运行，用户通过浏览器访问。

#### Scenario: 浏览器访问
- **WHEN** 用户访问驾驶舱
- **THEN** 系统 MUST 以 Web 页面形式提供服务，无需安装客户端程序

### Requirement: 模块承载边界
系统 SHALL 明确本次范围内各功能模块的归属：生产管理、库存管理、质量管理为三个业务模块，登录为统一访问前置，企业知识库与多用户登录不在本次范围内。

#### Scenario: 模块归属判定
- **WHEN** 需要判定某一功能是否属于本次系统底座承载范围
- **THEN** 生产管理、库存管理、质量管理 MUST 判定为在范围内，企业知识库与多用户登录 MUST 判定为不在范围内

### Requirement: 底座与业务模块分层
系统底座 SHALL 与业务模块分层，底座负责运行框架与登录，业务模块（生产/库存/质量）基于底座承载。

#### Scenario: 业务模块依赖底座
- **WHEN** 后续落地生产、库存、质量任一业务模块
- **THEN** 该模块 MUST 基于本系统底座承载，复用底座提供的运行框架与登录入口
