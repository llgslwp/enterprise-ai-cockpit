# Spec Delta

## ADDED Requirements

### Requirement: 多轮上下文与指代消解改写
系统 SHALL 支持多轮对话上下文：当用户追问含指代（「它 / 这个 / 那个 / 其」等）或省略主语、依赖上文时，系统 MUST 先将追问改写成完整独立查询，再进入工具调用，避免模型因单轮失忆答非所问。

#### Scenario: 首轮跳过改写（门控）
- **WHEN** 一次问答的 history 为空（首轮或新话题）
- **THEN** 系统 MUST 跳过改写，原样透传问题进入工具调用，不额外调用大模型

#### Scenario: 有历史才改写
- **WHEN** 一次问答的 history 非空（多轮追问）
- **THEN** 系统 MUST 调用公共改写函数，将含指代的追问改写为完整独立查询，并以改写后的查询进入工具调用

#### Scenario: 改写结果透出
- **WHEN** 系统完成 Query 改写
- **THEN** 系统 MUST 将改写后的查询作为 `rewritten_query` 字段随响应返回，供前端展示「已理解：XXX」；未改写（history 为空）时该字段为空，前端不展示

#### Scenario: 改写失败回退
- **WHEN** 改写返回空或调用失败
- **THEN** 系统 MUST 回退使用原始问题继续问答，不得因改写失败中断

#### Scenario: 历史范围与截断
- **WHEN** 构造改写上下文
- **THEN** 系统 MUST 仅取最近 6 条历史（约 3 轮），单条内容截断至数百字，防止 token 超限

#### Scenario: 公共能力复用
- **WHEN** agent 与知识库两个模块均需改写
- **THEN** 两者 MUST 复用同一公共改写函数，不得各自复制一份，保证口径一致

#### Scenario: 性能约束（LLM 豁免）
- **WHEN** 触发 Query 改写（多一轮 LLM 调用）
- **THEN** 该调用属 LLM 问答豁免类型，不套 200ms 常规查询约束，MUST 提供进度反馈，完成时给出完成提示

## MODIFIED Requirements

### Requirement: 对话主交互形态
系统 SHALL 以「对话」作为智能辅助决策的主交互形态，用户以自然语言提问，系统返回基于工具调用（含知识库检索）生成的回答。对话接口 SHALL 接受最近 N 轮历史，支持多轮上下文。

#### Scenario: 核心操作经对话驱动
- **WHEN** 用户以自然语言提出业务数据或知识问题
- **THEN** 系统 SHALL 通过对话返回基于工具调用或知识库检索生成的回答

#### Scenario: 多轮上下文
- **WHEN** 用户的追问依赖上文（含指代或省略主语）
- **THEN** 系统 SHALL 结合历史将追问改写为完整独立查询后再回答，不得按单轮孤立理解而答非所问
