# agent-core Specification

## Purpose

定义 Agent 核心能力：云端大模型接入层与自然语言意图识别。这是本项目作为「制造业 × Agent」典型案例的核心展示点，自然语言操作通过调用国内云端大模型实现，不本地部署。

## ADDED Requirements

### Requirement: 云端大模型接入
系统 SHALL 通过抽象接入层调用云端大模型（国内厂商），实现自然语言操作能力，不本地部署大模型。

#### Scenario: 调用云端大模型
- **WHEN** 系统需要理解并执行自然语言指令
- **THEN** 系统 MUST 通过云端大模型 API 完成，而非本地部署模型

#### Scenario: 厂商可切换
- **WHEN** 需要更换云端大模型厂商
- **THEN** 系统 SHALL 通过抽象接入层隔离厂商差异，更换厂商不改动业务逻辑

### Requirement: 自研轻量编排引擎
对话编排 SHALL 由系统自研的轻量编排引擎实现（意图识别、参数补齐、状态机、确认、反馈），而非依赖现成 Agent 框架；云端大模型仅作意图兜底分类。

#### Scenario: 编排逻辑自研
- **WHEN** 处理自然语言指令的意图识别、参数补齐、确认、反馈
- **THEN** 这些编排逻辑 MUST 由系统自有代码实现，而非由 LangChain / Dify 等现成框架承载

### Requirement: 自然语言意图识别
系统 SHALL 识别用户的自然语言操作指令，并将其映射到对应的既有计算链路。

#### Scenario: 触发写回操作
- **WHEN** 用户以自然语言发出「文件齐了，开始写回」等指令
- **THEN** 系统 MUST 识别意图为「写回」，并触发对应的写回计算链路

#### Scenario: 无法识别的指令
- **WHEN** 自然语言指令无法映射到任何既有操作
- **THEN** 系统 MUST 返回明确的无法识别提示，而非静默失败或错误执行

### Requirement: 对话主交互形态
系统 SHALL 以「对话为主、按钮为辅」作为人机交互主形态，核心操作以自然语言对话驱动，按钮 / 表单作为辅助与兜底。

#### Scenario: 核心操作经对话驱动
- **WHEN** 用户执行核心操作（上传、写回、排产、查汇总）
- **THEN** 系统 SHALL 支持以自然语言对话触发该操作，而非仅依赖按钮点击

### Requirement: 全局智能助手
系统 SHALL 提供一个全局可唤起的智能助手，理解当前用户角色与数据状态，并在角色职责范围内触发操作。

#### Scenario: 角色权限收敛
- **WHEN** 某一角色通过助手发出超出其职责范围的指令
- **THEN** 系统 MUST 拒绝执行，而非越权触发操作

### Requirement: 副作用操作确认
凡涉及写回、排产等有副作用的操作，系统 SHALL 在执行前向用户确认；查询类操作可直接返回。

#### Scenario: 副作用操作前确认
- **WHEN** 用户触发写回 / 排产等副作用操作
- **THEN** 系统 MUST 在执行前复述操作意图并请求确认，确认后方可执行

#### Scenario: 查询类操作直接返回
- **WHEN** 用户发起库存 / 台账 / 汇总 / 质量等查询
- **THEN** 系统 SHALL 直接返回结果，无需确认

### Requirement: 操作结果反馈
系统 SHALL 对每次操作返回明确的结果反馈：成功、部分成功、失败、无法识别四类，且结果可追溯。

#### Scenario: 成功反馈
- **WHEN** 操作成功完成
- **THEN** 系统 MUST 返回结果摘要与关键数字，并提供结果文件下载或图表入口

#### Scenario: 失败反馈
- **WHEN** 操作失败
- **THEN** 系统 MUST 说明失败原因与建议下一步，而非静默失败
