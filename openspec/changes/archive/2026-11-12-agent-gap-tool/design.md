# Design

## 工具语义（口径）

`query_gap` 回答「还差多少」，数据来自 V2.0 排产结果的**成品计划 + 半成品需求计划 + 缺口两列**：

| 字段 | 含义 | 正负语义 |
|---|---|---|
| 成品计划 | 该规格要产多少成品（块头 J/K 列） | 无正负 |
| 半成品需求计划（need） | 要生产多少半成品（需求量） | 恒 ≥ 0，**非缺口**，返回裸数字 |
| 装配缺口（gap） | 装配环节缺口 | 正=缺口（需补），负=富余 |
| 机加工缺口（machine，表头名「机加工生产计划」） | 机加工环节缺口 | 正=缺口（需产），负=富余 |

> **缺口仅含「装配缺口」「机加工缺口」两列**；「半成品需求计划」是需求计划量、不是缺口（值域实测：正 227 / 零 80 / null 58，无负数）。语义依据：缺口统计页前端已用「装配缺口/机加工列正数标红（粉红底红字）」确认「正数=缺口」；`null` 表示该配件无此工序。

粒度：V2.0 是「规格块（block_label）× 配件行」结构，每个规格块下有多个配件（如固定钢板、活动钳体、夹紧头…），每个配件有独立的成品计划 + 需求计划 + 缺口两列。**缺口按配件看、不跨配件合计**（固定钢板差 200 与活动钳体富余 100 不能抵消）。

## 数据源（复用确定性实现）

- `gap_stat.extract_gap_stat(gap_stat.resolve_result_file())`，返回 `products[品类].blocks[]`，每块含 `block_label`、`headers.plan1/plan2`（成品计划）、`rows[].gap{need,gap,machine}`（need=半成品需求计划、gap=装配缺口、machine=机加工缺口）。
- 该实现已通过「公式求值器 vs Excel 逐值 0 差异」验证，本次只读不改。

## 工具签名与三级粒度（与 query_stock 对齐）

```python
@tool
def query_gap(category: str = "", spec: str = "") -> str
```

| 调用 | 返回粒度 |
|---|---|
| 不带参数 | 全部 5 品类，每规格块「成品计划 + 正缺口配件」（精简，只列 gap/machine 任一为正的配件） |
| 带 category | 该品类所有规格块，同上精简 |
| 带 spec | 该规格块「成品计划 + 全部配件」（完整，含负缺口） |

正缺口判定：`gap>0 or machine>0`（「半成品需求计划」是需求计划、非缺口，不计入）。

## 规格匹配（数字指纹 + 前缀）

`block_label` 格式多样：加力 `80D/18"`、美式 `18"`、内管 `S73`、钻杆 `71-75`、套管 `73/89`。匹配策略：

```python
def _match_label(kw, label):
    kw_nums = re.findall(r"\d+", kw)
    label_nums = re.findall(r"\d+", label)
    if not kw_nums or not label_nums:
        return kw.lower() in label.lower() or label.lower() in kw.lower()
    if kw_nums == label_nums:                      # 精确等值：71-75 ↔ 71-75
        return True
    if kw_nums == label_nums[:len(kw_nums)]:       # 数字前缀：80 → 80D/18"；54 → 54-56
        return True
    return False
```

- `71-75`→钻杆钳 71-75；`73/89`→套管钳 73/89；`S73`→内管钳 S73（精确等值）。
- `80`→加力 80D/18"（前缀）；`54`→钻杆钳 54-56（前缀）。
- `95`→内管钳 S95（精确）+ 加力 95D/24"（前缀），两品类都返回，与 query_stock 处理「95」一致的合理歧义。
- 数字指纹精确匹配，杜绝「71」误伤「71-75」等子串误伤。

## 返回结构（JSON，示例）

- 「装配缺口」「机加工缺口」两列以**方向标注结构**返回，把「看负号判方向」这个模型最易错的活儿提前由确定性代码做掉——模型照读「缺口/富余」字段即可，无需再判符号。
- 「半成品需求计划」是需求计划量（恒 ≥ 0），返回**裸数字**，不做方向标注。

```json
{
  "说明": "基于最新排产结果；缺口仅含装配缺口、机加工缺口两列（正=缺口，负=富余）；半成品需求计划=需求计划量（非缺口）",
  "规格块": [
    {
      "品类": "钻杆钳",
      "规格": "71-75",
      "成品计划": {"成品计划": 604},
      "配件": [
        {"配件": "固定钢板", "半成品需求计划": 1414, "装配缺口": {"缺口": 0, "富余": 413}, "机加工缺口": null},
        {"配件": "固定齿块", "半成品需求计划": 1414, "装配缺口": {"缺口": 559, "富余": 0}, "机加工缺口": {"缺口": 0, "富余": 20237}}
      ]
    }
  ]
}
```

> 两轮修正记录：① 初版返回裸数字（`"装配缺口": -2273`），模型需自行把负号翻译成「富余」，曾出现「机加工缺口较大：固定齿块 -20237……（负数表示富余）」的自相矛盾；② 又把「半成品需求计划」误当缺口（做方向标注），经业务方纠正——缺口仅含装配缺口、机加工缺口两列，需求计划返回裸数字。

加力/美式双计划块（J/K 两列），成品计划用 `col_titles` 中文标题做 key，如 `{"成品计划80D": 100, "成品计划18\"": 50}`。

## 数据时效性

V2.0 排产结果由「排产统计」按钮覆盖式更新，`query_gap` 读的是**最新一次排产结果**，非实时台账。docstring 必须写明「数据来自最新排产结果，若刚更新了成品计划，需先在缺口统计页点『排产统计』」。这是与 `query_stock`（按月读台账）的关键差异，避免模型误以为缺口实时。

## 性能

`extract_gap_stat` 实测 130ms（第二次调用，排除首次加载），符合全局 NFR 常规查询 ≤200ms。agent 问答整体属 LLM 豁免类型，走既有「即时进度反馈 + 完成提示」。
