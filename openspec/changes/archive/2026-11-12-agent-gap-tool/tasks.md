## 返回结构修正（2026-11-12 二轮迭代）

- 问题：首次端到端模型输出「机加工环节缺口较大：固定齿块 -20237……（负数表示富余，够用）」自相矛盾——裸数字 `-20237` 让模型在「读符号（→富余）」与「读绝对值大小（→缺口大）」之间打架。
- 修正：缺口值从裸数字改为**方向标注结构**（`{"缺口": n, "富余": 0}` / `{"缺口": 0, "富余": n}`），把「判符号」这个模型最易错的活儿提前由确定性代码做掉，模型只需照读方向。
- 验证：1095 个工序字段方向标注与 gap_stat 原始值 0 差异；端到端两次提问机加工均正确表述为「富余、无缺口」。

## 缺口语义纠正（2026-11-12 三轮迭代，业务方纠正）

- 问题：业务方指出「半成品需求计划」被误理解为缺口——它是需求计划量（要生产多少半成品，恒 ≥ 0），**不是缺口**；「半成品计划缺口」仅含「装配缺口」「机加工缺口」两列。
- 依据：V2.0 表头真名 L 列=「半成品需求计划」、N 列=「机加工生产计划」（业务方口径「机加工缺口」）。值域实测：need 正 227/零 80/null 58（无负数，恒非负）；gap 正 81/负 93；machine 正 46/负 111。
- 修正：① 「半成品需求」字段名改回真名「半成品需求计划」、返回裸数字（不做方向标注）；② 「机加工」改名「机加工缺口」；③ 「哪些规格有缺口」判定剔除 need（只算 gap/machine>0）。
- 验证：1095 字段 0 差异；端到端问「71-75」「加力95」模型均正确区分需求计划 vs 缺口。
