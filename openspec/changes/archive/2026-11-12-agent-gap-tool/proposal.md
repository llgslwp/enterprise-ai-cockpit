# Proposal

## Why

「智能辅助决策」目前只有一个只读工具 `query_stock`，能回答「有多少（库存现状）」，但回答不了排产决策最核心的问题——「还差多少（缺口）」。

缺口 = 成品计划（要产多少）− 现有半成品/装配/机加工库存（已有多少），是排产决策的第一输入：只有知道「哪些规格、哪些配件还差多少」，才能决定排什么、排多少。当前 agent 面对「71-75 还差多少」「哪些规格有缺口」这类问题只能回答「我没有查询该数据的工具」，排产决策闭环缺了关键一环。

这是 `agent-decision`（2026-11-10）tasks 里已登记的「扩展到一批只读工具（缺口统计…）」的落地，属既定后续变更。

## What Changes

- **ADDED `agent-core` 缺口查询工具 `query_gap`**：查最新排产结果里各规格/配件的缺口（半成品需求、装配缺口、机加工）与成品计划，正数=缺口（需补/生产）、负数=富余（够用）。
- 复用既有确定性实现 `gap_stat.extract_gap_stat` + `resolve_result_file`（已 0 差异验证、性能优化到 130ms），不重写计算逻辑——延续「数据层复用确定性实现、模型只转述」铁律。
- 只读、无副作用，延续 `agent-core` 的「只读工具边界与写操作拦截」约束。

## 本次范围边界

- **本次做**：新增 `query_gap` 一个只读工具 + docstring「使用时机」+ 数据 0 差异回归 + 端到端验证。
- **本次不做（后续变更）**：产能查询、排产计划、质量合格率、知识库检索等工具（`agent-decision` tasks 已登记，各自另行 propose）；写操作工具 + 人工确认通道。

## Capabilities

### Modified Capabilities

- `agent-core`：新增「缺口查询工具」requirement（ADDED）。

## Impact

- **数据源**：`data/raw/半成品生产计划V2.0.xlsx`（排产结果基底，覆盖式更新，非按月台账，故无 month 参数）。
- **依赖既有能力**：`semi-finished-planning`（`gap_stat` 提取 + `formula_eval` 公式求值，已 0 差异验证）。
- **性能**：`extract_gap_stat` 实测 130ms（≤200ms 常规查询约束）；agent 问答整体属 LLM 豁免类型。
- **不引入**：新数据源、新第三方依赖。
