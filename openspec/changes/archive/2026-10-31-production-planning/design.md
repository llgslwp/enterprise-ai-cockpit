# Design

## Context

底座（system-foundation）与库存数据建模（inventory-data-model）已归档固化：6 份源文件已建模，读取层采用字段无关设计，数据边界为「读本地已导出文件、不做 ERP / 腾讯文档对接、不做清洗」。本变更在此地基上实现生产管理的两条计算链路（回填 + 半成品排产），产出本地结果文件。

关键约束（来自已归档规范与用户访谈）：
- 数据实时性：每次计算前重读最新文件（带日期前缀按生成日期取最新；生产计划为固定名）。
- 名称/规格映射关系：`example/` 文档为高可信参考，真实文件验证性抽查后直接采用。
- 缺口方向：正数 = 缺口（需生产），零/负数 = 富余。

## Goals / Non-Goals

**Goals:**
- 一期：完整跑通「回填链路」与「半成品排产链路」，产出保留 Excel 公式的本地 V2.0 结果文件。
- 一期产出的 V2.0 沿用现有「6 品类 sheet」结构（加力 / 美式 / 内管钳 / 钻杆钳 / 套管钳 / 配件-颜色），不重构。

**Non-Goals:**
- 二期：用代码复刻公式逻辑、自动上传腾讯文档、V2.0 数据结构重构为「每规格一个 sheet」。本次不实施，仅在工件中登记。

## Decisions

### 决策 1：公式列「保留 Excel 公式」而非「代码算值」
一期生成的 V2.0，J/K/L/M 列写入 Excel 公式（如 `=L4-H4-I15-I16`），由 Excel 打开时计算。备选「代码直接算值」被否，因用户明确「先用已有公式跑通、代码复刻留二期」。代价是一期结果依赖 Excel 打开才能看到数值，这是接受的折中。

### 决策 2：一期沿用 6 品类 sheet 结构
不提前做「每规格一个 sheet」的重构（那是二期目标）。一期目标是复现现有 V2.0 形态，确保链路跑通、可对照真实模板验证。

### 决策 3：结果文件输出到 `data/` 下独立子目录
回填结果与 V2.0 结果写入 `data/output/`（或类似），与 `data/raw/` 的输入源分离，避免覆盖源文件、保持可溯源。

### 决策 4：名称/规格映射作为独立可查规则模块
映射关系（借用、规格归一、排除件等）集中在一个规则模块中，供回填与排产共用，避免两处重复且便于二期重构时替换。

### 决策 5：规格借用规则以《产品工艺总汇_永久记忆.md》第九章「通用配件表」为权威基准
- 借用关系是**三元映射**（产品线 × 配件 × 基准规格 → 通配规格），不是纯数字双向/单向对。此前记忆中的 `95↔108`、`132↔152`、`71–75借89–95` 是权威表的不完整摘抄，作废。
- 权威表结构化为常量表硬编码进 `mapping.py`，作为唯一基准；V2.0 文件的「借用行/承接行」标记仅作交叉验证，不反向推导规则。
- 数据源文件：`docs/产品工艺/产品工艺总汇_永久记忆.md`（第九章），配套术语/产品目录见同目录 `产品目录与术语.md`、`产品-钢材对应表.md`、`工艺路线索引.md`。
- 借用方向语义：某规格的某配件标记为「借用」时，其需求并入基准规格，本规格**不单独排产**（对应 V2.0 的「见XX」标注）。

## Risks / Trade-offs

- [缺口方向错误] → 通过真实数据验证性抽查固化「正数 = 缺口」，并在 spec 中显式规定，避免反向实现。
- [预留空行污染] 成品台账品类明细含 `(预留行)` 空行 → 回填与排产计算前过滤空行（不属清洗，属计算输入的有效行识别）。
- [名称/规格映射不精确] 映射关系虽高可信，仍可能有个别规格对不上 → 计算时对未命中项单独记录并暴露，而非静默跳过。
- [一期结果依赖 Excel 公式] 结果数值需 Excel 打开才能验证 → 一期验收时用真实文件对照模板核对结构与公式，二期再补代码算值。

## Open Questions

- 「最新文件」按文件名日期前缀识别的具体匹配规则（如 `261027` 的解析方式），待 apply 阶段结合真实文件名敲定，不影响 spec 与任务拆解。
