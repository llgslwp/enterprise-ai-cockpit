# Proposal

## Why

生产管理是需求说明书的主轴：利用已导出的 ERP 库存数据与生产计划，产出可指导实际投入生产的「半成品生产计划 V2.0」。当前底座（system-foundation）与库存数据建模（inventory-data-model）已就位，但「从库存 + 生产计划 → 半成品缺口」的计算逻辑尚未实现，生产负责人仍靠人工在 Excel 里滚动公式，效率低且易错。

## What Changes

新增生产管理一期能力，覆盖两条业务链路，并明确「一期 / 二期」工程分界：

- **回填链路**：把成品台账的入库记录匹配到生产计划的「当月实际完成」列（F 列），形成实际完成回填。
- **半成品排产链路**：从 6 份源（毛坯库 / 车间在产品 / 半成品库 / 外协 / 在产品装配 / 成品计划）重算「半成品生产计划 V2.0」，产出含关键工序缺口的本地结果文件。
- **本地产出 V2.0**：生成的 V2.0 文件**保留 Excel 公式本身**（J 成品计划 / K 半成品需求计划 / L 装配缺口 / M 机加工生产计划），由 Excel 计算，不依赖代码复刻公式逻辑。
- **缺口方向语义固化**：**正数 = 缺口（需生产）**，零 / 负数 = 富余（无需补产）。这是纠正过的一次方向性歧义，必须写入规格。
- **二期工程（本次不实施，仅登记为后续任务）**：① 用代码复刻公式逻辑（含「黑箱可验证」方案）② 自动上传腾讯文档 ③ V2.0 数据结构重构为「每品类每规格一个独立 sheet」。

## Capabilities

### New Capabilities
- `production-backfill`: 成品台账入库记录回填到生产计划的当月实际完成列，作为实际完成数据的统一来源。
- `semi-finished-planning`: 从 6 份库存源 + 成品计划重算半成品生产计划 V2.0，计算关键工序缺口（正数 = 缺口），产出保留 Excel 公式的本地结果文件。

## Impact

- **新增代码**：生产管理模块（`modules/production/`），回填与排产两条链路的实现。
- **依赖既有能力**：`inventory-data-model`（读取 6 份源文件）、`data-access`（读本地已导出文件，不连 ERP / 腾讯文档）。
- **数据实时性约束**：每次计算前重读最新文件（带日期前缀按生成日期取最新；生产计划为固定名）。
- **规则依据**：`example/` 目录的 5 份开发文档 + `data/raw/` 真实文件做验证性抽查，作为高可信参考；名称/规格映射关系直接采用（其可靠性经 4 个月近百次真实数据验证）。
- **不引入**：腾讯文档 API 对接、ERP 对接、数据清洗（这些维持 `data-access` 既有边界）。

## 二期工程登记（仅记录，不实施）

> 来源：任务 4.1。以下三项在本次变更中**不实施**，登记于此供后续独立变更提案启动。

1. **代码复刻公式逻辑**：一期 V2.0 的 J/K/L/M 列保留 Excel 公式、由 Excel 打开时计算，依赖 Excel 才能看到数值。二期用代码复刻公式逻辑（如 `=L4-H4-I15-I16` 的机加工缺口、J/K 成品计划的 ΣE−ΣF 等），并配套「黑箱可验证」方案 —— 即代码算值与 Excel 公式算值逐格对照，差异为零方可验收。
2. **自动上传腾讯文档**：一期结果仅本地产出（`data/output/`）。二期打通腾讯文档 API，把重算后的 V2.0 自动写回/上传到腾讯在线文档，替代当前人工粘贴。
3. **V2.0 数据结构重构为「每品类每规格一个独立 sheet」**：一期沿用现有「6 品类 sheet」结构。二期把每个品类下的每个规格拆成独立 sheet，便于独立排产、独立回写与增量更新。
