# Design

## Context

RAG 问答层（knowledge-base）此前从 `docs/产品工艺/`、`docs/公司制度/` 直接读文件，知识域为四域（生产工艺/作业指导书/行业标准/公司制度）。新增知识管理模块（knowledge-management）后，出现了「文件两处存放 + 分类两套体系」的不一致。本次统一为：**知识管理是唯一数据源**，**入库类型即知识域（三域）**。

## Decisions

- **单一数据源**：RAG 的文档加载（`loaders.load_all`）改为从知识管理文件库 `data/knowledge/` 读取，通过 `meta.json` 定位文件；`docs/` 目录退役为源备份，不再参与检索。

- **知识域 = 入库类型（三域）**：`DOMAIN_NAMES = ["工艺类", "制度类", "知识类"]`，与知识管理入库类型一一对应。语义映射：
  - 工艺类 ← 原「生产工艺」+「作业指导书」
  - 制度类 ← 原「公司制度」
  - 知识类 ← 原「行业标准」

- **加载规则（三条）**：
  1. 排除 `index/` 子目录（只存 RAG 索引，不含原始文件）；
  2. 跳过 `status=disabled` 的停用文件；
  3. 只取 `current_version` 对应版本文件，历史版本不进索引。

- **索引落地**：仍为 `data/knowledge/index/`（库内派生子目录，与文件库同属一个知识库根，避免两个平级目录的分离坑）。

- **域枚举 vs 范围描述**：`router.route_domain` 的域枚举改为三域；`is_offtopic`、`chain._SYSTEM`、离题文案描述的是「知识库覆盖的内容范围」（管钳工艺/作业/标准/公司制度），该范围在三域下不变，故保留原文。

## Risks / Trade-offs

- [扫描版 PDF 留二期] `作业1.pdf`、`作业2.pdf`、`QB_T2508-2016.pdf` 为扫描版（无文字层），`load_pdf` 跳过并提示 OCR 留二期，暂不进索引。
- [三域粒度] 三域比四域更粗，「生产工艺」与「作业指导书」合并为「工艺类」，靠检索内容区分，不再按域细分；这是用户拍板的取舍。
- [索引需重建] 数据源切换后，旧索引（若有）失效，须在 2 号高配机重新 `build`。
