# Design

## Context

库存管理已有数据层（`inventory-data-model` 读取五类 ERP 库存与成品台账，`inventory-status` 提供汇总/查询/预警），前端为浅色单页。本次改造复用既有数据层与预警逻辑，仅新增大屏可视化层与重点规格清单机制。

成品台账（`data/raw/2026年成品入出库_新台账v8.1.xlsx`）为 WPS 坏样式文件，读前须 `ensure_readable` 修复；其「汇总看板」sheet 表头在第二行，C4~C39 为 12 月×3 列（入库/出库/结存），C40/C41/C42 为全年入库/出库/年末库存。品类映射：台账原始类别「铸铁管钳」→ 展示品类「美重」。

## Goals / Non-Goals

**Goals:**
- 4 页深色大屏（总览/占比/明细/缺口），复用深色科技风样式（与生产大屏一致）。
- 重点规格开口式清单机制，增删勾选即时生效。
- 数据用台账实时精确计算，不硬编码示意值。

**Non-Goals:**
- 不改动 `inventory-status` 既有的汇总/查询/预警数据口径。
- 不做规格名「简化映射」（设计稿中简化名无明确规则，已确认取消）。
- 不做库存大屏的数据下钻、多月份切换（当前固定 10 月）。

## Decisions

1. **新能力 `inventory-dashboard` 独立于 `inventory-status`**：前者管「大屏可视化 + 重点规格」，后者管「数据聚合与预警」。理由：可视化形态与数据能力解耦，未来换皮肤或加页面不污染数据 spec。备选：并入 inventory-status（否决，会模糊能力边界）。

2. **重点规格用「独立清单表 + 全量打勾」**：新建 `data/raw/重点关注规格.xlsx`，列出全部 176 个真实规格 + 「是否重点」列，用户勾选。理由：与既有「库存底线配置表」的开口式范式一致，用户无需手敲规格名，AI 也能直接读文件。备选：代码写死清单（否决，改规格需改代码）；复用底线表（否决，用户明确要独立）。

3. **清单匹配键用台账原始类别名**：清单「类别」列存台账原始名（如「铸铁管钳」），与台账行精确匹配；展示时统一映射为 6 品类名。理由：避免「美重 vs 铸铁管钳」名实不一致导致匹配失败。

4. **重点规格数据走独立接口 `/api/inventory/focus-stats`**：返回 products（按品类分组）+ flat（平铺）+ count。理由：明细页和 AI 助手共用同一数据源，口径一致。备选：复用 flow-stats 再前端过滤（否决，会把「重点」判定逻辑放到前端，重复且易漂移）。

5. **前端图表用 ECharts 6.1.0，渲染时机用 watch + requestAnimationFrame**：数据到位后经 `watch` → `nextTick` → `requestAnimationFrame` 再 `echarts.init`。理由：避免 `v-if` 分支刚插入时容器尺寸为 0 导致图表空白（本变更实际踩过的坑）。

6. **AI 助手在 query 意图内加「重点规格」关键词分支**：`detect_intent` 的 query 关键词集增加「重点规格/重点关注/关注规格/规格明细」，`_direct_reply` 的 query 分支对重点规格查询调用 `build_focus_stats` 返回真实数据。理由：最小侵入，不改变既有意图分类结构。

## Risks / Trade-offs

- [后端改代码后未重启导致新路由 404] → 已踩坑：reload=True 对新增文件/路由监听不可靠；须重启后端服务，不能只依赖热重载。
- [清单表被 WPS/Excel 打开锁定] → 读取用 data_only 只读加载不受影响；写入（程序生成模板）会 PermissionError，需用户先关闭文件。
- [重点规格匹配依赖三元组精确相等] → 清单类别/规格/特征任一字符不一致即漏匹配；生成模板时直接从台账反查，降低手填错误。
- [ECharts 容器尺寸为 0 渲染空白] → 用 watch + rAF 兜底，并给容器显式 width:100%。
