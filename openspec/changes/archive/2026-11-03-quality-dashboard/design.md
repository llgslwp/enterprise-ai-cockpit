# Design

## Context

质量模块当前仅 `modules/quality/router.py` 空壳占位。需新增质量看板（车间抽检）与原料来料检验两个只读能力。数据源为本地 Excel（已核实实际结构，非腾讯文档）：

- `data/raw/车间各工序质量抽检记录表.xlsx`：WPS 坏样式文件（openpyxl 直接读抛 Fill 错误），需 `ensure_readable` 修复。子表为月份（`1-2月份`、`3月份 `、`4月份  `…`10月份`，含尾随空格），另有非月份 sheet `Sheet4`、`报废` 需排除。表头在第 1 行、26 列：日期/姓名/工段（机加工/热处理/装配）/配件名称/规格/工作量/抽检数量/合格数量/合格率/问题描述/处置方式（返工/更换零件/让步接受/报废）。合格率列存小数（1=100%）。
- `data/raw/毛坯来料检验记录v2.xlsx`：sheet「来料检验记录」第 1 行空、第 2 行表头，10 列：检验日期/供货单位/物料名称/规格/来料数量/抽检数量/检验结果/问题描述/处置方式/硬度检测HRC。

沿用既有模块约定：`modules/quality/` 后端 + `web/src/views/Quality.vue` 深色大屏，数据实时读取不缓存。

## Goals / Non-Goals

**Goals:**
- 车间抽检质量看板（KPI + 趋势折线 + 4 维问题 TOP + 严重预警列表）+ 原料来料检验看板，均为只读。
- 月份子表自动发现、缺月回退最近可用月并附 note。
- 数据源标注（文件名 + 更新日期）。

**Non-Goals:**
- 不接腾讯文档 API、不写回数据。
- 不实现完整根因分析业务规则（六分类/三分级/四预警/建议动作，来自 `00-质量分析规则.md`）——留第二阶段。
- 不引入历史月份回放（`/api/history/quality`）——本期仅当月/指定月 + 回退。

## Decisions

1. **数据源用本地 Excel 而非腾讯文档**：用户拍板（参考文档 §2 写腾讯文档在线，但实际数据源已导出到 `data/raw/` 本地，且既有 inventory/production 均走本地文件）。选本地，避免引入 sheet-mcp/腾讯文档 SDK 依赖。

2. **车间抽检表读月份子表 + 排除非月份 sheet**：月份子表名满足「含"月份"或"月"」且非 `Sheet4`/`报废`；用 `ensure_readable` 先修复 WPS 坏样式（复用 `plan_file_utils`）。子表名有尾随空格，归一化时 `strip()`。

3. **合格率口径**：`Σ合格数量 ÷ Σ抽检数量 × 100`，保留 1 位小数；忽略表头行与「日期」为空的行（历史脚本曾因未去空行导致记录虚高）。「合格率」列本身不用（它是行内小数，不等于整体口径）。

4. **问题 TOP 按条数而非件数**：四个维度（问题描述/配件/工段/姓名）分别 `count`，降序 Top 8；仅取「问题描述」非空的行。

5. **严重预警**：处置方式 ∈ {报废, 返工, 让步接收, 让步接受}（「让步接收/让步接受」两写法都要命中）。

6. **月份回退**：`month` 缺省时取当前系统月；若该月无子表或无「日期」非空的行，回退到最近可用月，返回 `note`。

7. **工段容错**：工段可能为空或写法不统一，空值展示为「未填」。

8. **前端单页多分区**：`Quality.vue` 一个页面内，顶部月份选择器 + 车间抽检 KPI/图表 + 原料检验分区，复用现有深色大屏样式与 ECharts 本地渲染（对齐 InventoryOverview/InventoryShare 的做法）。

## Risks / Trade-offs

- **WPS 坏样式** → 复用 `ensure_readable` 自动修复；原始件更新后旧 `_修复` 派生件过期，定位时取 mtime 最新（沿用 inventory 的定位语义）。
- **月份子表命名不统一（尾随空格、`3月份 ` 等）** → 归一化 `strip()` 后匹配；`1-2月份` 单独处理为「1-2月」标签。
- **合格率列误导** → 明确只用「合格/抽检」口径，代码注释与 spec 均已标注，避免误用。
- **工段为空** → 展示「未填」，不因空值崩溃。
- **原料检验第 1 行空表头** → 读取从第 2 行表头开始定位，避免照抄车间抽检表的「第 1 行表头」假设。
- **缺月** → 回退 + note，且失败降级（该模块异常提示，不让整个服务 500）。
