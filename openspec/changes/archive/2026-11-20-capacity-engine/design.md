# Design

## 工具语义（口径）

`query_capacity` 回答「以现有资源最多能生产多少」，数据来自 V2.0 半成品计划的**现有量列（C 毛坯库 / H 半成品 / I 装配）**，按两维口径取瓶颈：

| 维度 | 含义 | 公式 |
|---|---|---|
| 第一维度（装配） | 已有简易钳体 + 齿块 + 外管，能直接装几把 | X = min(组装简易钳体·I, 活动齿块·H, 自由钳外管·H) |
| 第二维度（组装追加） | 齿块和外管还有剩余时，再组装简易钳体追加 | Y = min(floor(min(配件现有量÷用量)), 剩余齿块, 剩余外管) |

生产链：配件 → 组装 → 组装简易钳体 → 热处理 → 装配（+活动齿块 +自由钳外管）→ 成品。

## 两维 BOM（钻杆钳，配置表）

**第一维度**（每把用量均为 1，取数位置见括号）：

| 配件 | 取数列 | 位置 |
|---|---|---|
| 组装简易钳体 | I | 装配 |
| 活动齿块 | H | 半成品 |
| 自由钳外管 | H | 半成品 |

**第二维度**（1 个组装简易钳体 =）：

| 配件 | 用量 | 取数列 |
|---|---|---|
| 固定钢板 | 2 | C 毛坯库 |
| 活动钳体 | 1 | H |
| 夹紧头 | 1 | H |
| 长销子 | 2 | H |
| 短销子 | 1 | H |
| 组装齿块+方块座 | 2 | H |

## 三维 BOM（加力钳，公制规格，配置表）

加力钳 1 把 = 8 件各 1：加力钳体、加力外管、加力小钳口、加力大钳口、固定帽、加力螺母、把手、加力内管（镀锌）。

装配分步预装成两个组合件（装配 I 列）：
- 三合一「加力钳体+外管+小钳口」
- 二合一「加力钳体+外管」

| 维度 | 组合件（装配I） | 补件（取数列，每件用量 1） |
|---|---|---|
| 第一维度 | 三合一 | 大钳口(H+I)、固定帽(H+I)、螺母(H+I)、把手(H+I+F)、内管(H+I) |
| 第二维度 | 二合一 | 小钳口(H+I)、大钳口(H+I)、固定帽(H+I)、螺母(H+I)、把手(H+I+F)、内管(H+I) |
| 第三维度 | 无（裸件凑装） | 钳体(H)、小钳口(H)、大钳口(H)、固定帽(H)、螺母(H)、把手(H+F)、内管(H)、外管(F+H) |

> 取数列：H=半成品、I=装配、F=待处理；「H+I」= 两列求和。
> 特殊：把手全维度额外计入待处理 F（业务方 2026-11-20 补充）；外管第三维取「待处理+半成品」(F+H)。
> 第三维度「半成品里的」只取 H 列（不含装配 I），与第一/二维「半成品+装配」取数不同。
> 补件维度间顺序消耗（第二维用第一维剩余；第三维从半成品独立取数）。

## 特殊规则

1. **组合件「组装齿块+方块座」**：由固定齿块 + 方块座组装而成的必需组合件，产能**只看它自身数量**，不单独看固定齿块/方块座是否足够。
2. **整除向下取整**：固定钢板 3÷2=1.5 → 1 个，不够 1 套不算。
3. **第二维度配件在第一维度不消耗**：用其完整现有量。
4. **活动齿块 1 倍**（业务方 2026-11-20 已改原始文件公式，原 2 倍为误）。

## 配置驱动架构（阶段 1 骨架）

产能计算引擎分两层：

- **通用引擎** `_calc_capacity_core(rows)`（钻杆钳两维）/ `_calc_capacity_jiali_core(rows)`（加力钳三维）：纯计算逻辑，输入「配件名 → 现有量」，输出「多维度可产 + 瓶颈」，不读文件、可单元测试。
- **品类配置** `_DIM1` / `_DIM2`（钻杆钳）、`_JIALI_DIMS`（加力钳）：各维度的 BOM（配件名 + 取数列 + 用量）。

**统一口径 = 「组合件递减多维 min」**（2026-11-20 业务方口述锁定，取代此前错误的「顺序贪婪竞争」）：

- 装配是分步的：先把若干件预装成「组合件」，成品再补剩余件。
- 产能按「组合件已装到哪一步」分维度，组合件从最高级递减到「无（裸件凑装）」。
- 每维可产 = min(组合件数量, 各补件可用量)；补件在维度间顺序消耗（下一维用上一维剩余）。
- 钻杆钳 = 两维（1 级预装：组装简易钳体）；加力钳 = 三维（2 级预装：三合一 → 二合一 → 裸件）。同一套逻辑，仅预装层级数不同。

阶段 2 在此骨架上，接入借件规格竞争分配 / 借用规则 / 跨品类外管借用 / 组合件蕴含 / 外管焊接 / 毛坯规则（复用同一「组合件递减多维 min」引擎，而非旧的顺序贪婪脚本）。

## 支持规格清单（阶段 1）

`SUPPORTED_SPECS = {"钻杆钳": ("54-56", "71-75"), "加力": ("95D",)}`。

**钻杆钳**：
- **独立规格**（54-56、71-75）：三件均自有库存，直接两维计算。
- **借件规格**（89-95、114-117）：活动齿块/自由钳外管「见71-75」，无独立库存，阶段 1 返回「借件规格，待阶段 2 支持」，**不孤立算**（否则算成 0，语义错误）。
- **借用规格**（成品计划=0：139-146 / 86-91 / 58-62 / 108-110）：不单独排产，不算。

**加力钳**：
- **支持规格**（95D，公制）：块标签 `95D/24"`，块内按 B 列规格过滤 `spec=95` 的配件行，三维计算。
- **借用规格**（108D 借 95、152D 借 132）：阶段 1 不支持，待阶段 2。
- **英制**（18"/24"/36"/48"）：与公制共享件，阶段 1 不支持，待阶段 2。

判定依据：钻杆钳看块内三件是否出现「见XX」借用文本（`is_borrow`）或成品计划为 0；加力钳看块内是否含其他规格的配件行（借用）或是否英制侧。

## 数据源

`gap_stat.extract_gap_stat(gap_stat.resolve_result_file())`，读 `products["钻杆钳"].blocks[]` 的 `block_label`、`rows[].cells`（C/H/I 现有量）、`rows[].gap_text`（借用行「见XX」文本）。已通过「公式求值器 vs Excel 逐值 0 差异」验证，本次只读不改。

## 工具签名与粒度

```python
@tool
def query_capacity(category: str = "", spec: str = "") -> str
```

| 调用 | 返回粒度 |
|---|---|
| 带 spec | 该规格两维产能明细（可产把数 + 瓶颈件 + 第一/第二维度逐配件） |
| 带 category（或空） | 该品类全部支持规格的可产汇总（精简：规格 + 可产 + 瓶颈） |

## 返回结构（JSON，示例）

```json
{
  "品类": "钻杆钳",
  "规格": "71-75",
  "总可产把数": 627,
  "第一维度可产": 627,
  "第二维度追加": 0,
  "瓶颈件": ["自由钳外管"],
  "第一维度": [
    {"配件": "组装简易钳体", "位置": "装配", "现有量": 912, "可产把数": 912, "是否瓶颈": false},
    {"配件": "活动齿块", "位置": "半成品", "现有量": 1404, "可产把数": 1404, "是否瓶颈": false},
    {"配件": "自由钳外管", "位置": "半成品", "现有量": 627, "可产把数": 627, "是否瓶颈": true}
  ],
  "第二维度": {"触发": false, "可新组简易钳体": 1, "追加": 0, "说明": "活动齿块与自由钳外管未同时剩余，第二维度不触发"}
}
```

> 返回结构自带方向与瓶颈标记（`是否瓶颈`），模型照读即可，不靠绝对值大小判方向。

## 提示词止血

`agent.py` 系统提示词增加硬规则：**「缺口 ≠ 可用量、缺口 ≠ 可产数量」**；「最多能生产 / 可产 / 产能」类问题 MUST 用 `query_capacity`；无匹配工具时明确说「暂无此工具」，禁止拿 `query_gap` 缺口去减成品计划硬凑。

## 真值锚点（业务方对账用，2026-11-20 确认正确）

| 品类 | 规格 | 可产把数 | 瓶颈件 | 关键现有量 |
|---|---|---|---|---|
| 钻杆钳 | 54-56 | **210** | 组装简易钳体 | 简易钳体 210 / 齿块 1387 / 外管 2703 |
| 钻杆钳 | 71-75 | **627** | 自由钳外管 | 简易钳体 912 / 齿块 1404 / 外管 627 |
| 加力 | 95D | **1176** | 三合一/内管镀锌/钳体 | 945+231+0；三合一I=945、二合一I=1277、内管H=1176 |

加力 95D 三维分解（业务方对账确认 1176）：
- 第一维 945（瓶颈=三合一组合件）；第二维 231（瓶颈=内管镀锌）；第三维 0（瓶颈=钳体半成品=0）。

## 性能

- 单规格 `calc_capacity` 实测 ~135ms；全规格 `calc_capacity_all` 只读一次文件、循环纯计算，从 1258ms 优化到 ~132ms（≤200ms 约束）。
- agent 问答整体属 LLM 豁免类型，走既有「即时进度反馈 + 完成提示」。
