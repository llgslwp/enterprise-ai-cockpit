# Design

## Context

现有质量模块采用「reader（读 Excel）→ aggregate（聚合）→ router（接口）」三层结构，`modules/quality/aggregate.py` 已有 `build_quality`、`build_material_inspection` 等聚合函数。本次新增工具能力复用同一数据源（`data/raw/` 下的抽检记录表），前端沿用深色科技风大屏风格与 ECharts 图表。8D 闭环需引入「写回」能力，但必须隔离于原始质检 Excel。

## Goals / Non-Goals

**Goals:**
- 控制图、四预警、8D 三者共用同一套抽检数据，结果可量化、可对照验收。
- 8D 写回落在独立台账，与只读的原始数据彻底隔离。

**Non-Goals:**
- 不做任何对原始质检 Excel 的写回或修改。
- 不引入数据库；台账用轻量 JSON 文件。
- 不做多用户权限隔离（沿用现有单机单用户登录态）。

## Decisions

- **控制图算法**：p 图，CL=Σ不合格/Σ抽检，逐日 UCL/LCL = CL ± 3·√(CL·(1−CL)/n)，随 n 变化。破限判定为当日不合格率超出控制限。备选方案（Xbar-R 图）因抽检是计数型数据（合格/不合格）不适用，故用 p 图。
- **姓名异写归并**：按「姓氏+名字近似」归并（同音/近形），如「杨韶磊/杨邵磊」。备选「按字面统计」会漏判反复出现，弃用。
- **问题六分类**：关键词匹配 + 「第六类」兜底（暂定名，后续据数据重命名）。第六类名不硬编码为具体含义，保留扩展性。
- **8D 台账**：`data/8d_closure.json`，原子写（写临时文件再替换），D5–D8 字段独立存储，读取时与派生卡合并。
- **8D 双维度**：人员反复（人+分类）与跨月反复（工段+问题主题）两档，卡片带 `type` 字段区分；跨月锚点按「工段+主题关键词」归并问题描述异写（如「试验/实验、螺纹裂/齿崩/齿推」）。
- **接口**：`/spc`、`/8d` 为 GET（只读），`/8d/update`、`/8d/reset` 为 POST（写回），统一走 `require_login` 依赖。

## Risks / Trade-offs

- [跨月锚点触发阈值过宽（跨月即触发）可能产生较多轻微卡片] → 预留按累计次数过滤的扩展点，后续可按业务加阈值。
- [六分类关键词表依赖人工维护，新问题描述可能落进「第六类」] → 第六类作为可命名兜底，后续据数据反查补关键词。
- [姓名归并无法穷尽所有异写] → 归并规则集中在一处（`_canonical_name`），后续可扩展名单。
- [8D 台账为 JSON 文件，无并发锁] → 单机单用户场景可接受；原子写保证写入不损坏文件。
