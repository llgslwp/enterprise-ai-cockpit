# Design

## Context

库存数据地基（`inventory-data-model`）已就位：`app/data_model/` 提供 `load_category` / `load_all` / `load_product_ledger` 读取六类库存数据（五类 ERP 库存 + 成品台账），字段按原始字段原样承接，字段字典可溯源。本变更在其上实现「看板聚合 / 明细检索 / 预警判定」三个业务能力，不改动数据模型层。

关键约束（沿用既有）：
- 数据实时性：每次查看前重读 `data/raw/` 下最新文件。
- 不连 ERP / 腾讯文档，不洗数据。
- 前端为 Vue3 SPA，接口走 REST + JSON（`/api/` 前缀）。

## Goals / Non-Goals

**Goals:**
- 提供三个接口：`/api/inventory/summary`（汇总看板）、`/api/inventory/search`（明细查询）、`/api/inventory/alerts`（预警）。
- 复用 `app/data_model/` 读取层，不重复造读取逻辑。
- 预警阈值可配置（开口式 Excel 配置表，按「类别+规格+特征」定义底线，未定义不预警）。

**Non-Goals:**
- 不做安全库存阈值的网页设置界面（本期用独立 Excel 配置表，后续可加网页维护）。
- 不做库存变动历史 / 时间趋势图（数据无可靠时间维度）。
- 不改动 `inventory-data-model` 的读取层与字段字典。

## Decisions

### 决策 1：三个接口复用统一读取层，聚合逻辑放 `modules/inventory/`
看板/检索/预警都先经 `app/data_model` 把六类数据读成 `InventoryTable`，再做聚合与判定。理由：读取逻辑已存在且字段原样承接，业务层只关心「怎么算」，不碰「怎么读」。

### 决策 2：预警阈值用「开口式 Excel 配置表」驱动
库存底线存于一张独立 Excel 表（`data/raw/库存底线配置表.xlsx`，或用户自建的等价文件），字段为「类别 / 规格 / 特征 / 库存底线」。每次统计库存时动态扫描该表，按「类别+规格+特征」三维匹配成品台账汇总看板；未定义的规格一律不预警。理由：满足「可设置 + 开口式」——配置是数据而非代码，用户随时加底线行即时生效，无需改代码、无需重启。备选「统一默认值 + 按类别覆盖的 JSON 配置」被否，因用户明确要求由他维护 Excel 表、按产成品逐条定义底线、未定义不预警。

### 决策 3：预警对象与结存口径——成品台账汇总看板 + 「年末库存」字段
预警针对「主要产成品」，数据源取成品台账「汇总看板」sheet（一行一个「类别/规格/特征」）。「当前结存」取台账专门的 **「年末库存」字段**（台账维护方认定的当前库存数），而非按月份推算。理由：台账的 11/12 月结存列为「顺延值」（沿用 10 月结存、入库出库均为 0），按「最新月度结存」推算会误判；「年末库存」是台账专门维护的当前库存口径，一个字段直接可比，最准确、最省心。判断式简化为 `年末库存 < 库存底线 → 预警`。

### 决策 4：五类 ERP 库存纳入看板与明细，但不参与成品底线预警
五类 ERP 库存（毛坯/半成品/外协/车间在产品/在产品装配）进入「汇总看板」与「逐物资明细查询」，其「现有存量」列用于看板展示；但它们不参与「成品库存底线」预警（预警只针对成品台账的产成品结存）。理由：需求明确预警对象是「主要产成品」的库存底线，五类库存是半成品/毛坯等中间态，不设底线预警。

## Risks / Trade-offs

- [成品台账字段异构] 成品台账「结存数量」与五类库存「现有存量」含义不同 → 看板中分开展示或明确标注，避免误读为同类存量。
- [底线配置表格式需用户提供] 库存底线配置表由用户维护，其「类别/规格/特征」须与台账汇总看板的取值一致才能匹配命中 → 交付时给出模板与字段对齐说明，匹配不到的底线行单独提示（不静默丢弃，便于用户核对）。
- [结存月份动态识别] 「最新已填月份」的自动识别依赖台账各月「X月结存」列非空判断 → 容错处理：若某月结存列全空则视为未填，取上一个非空月份；极端情况（全部为空）该规格不参与预警。
- [数值脏数据] 「结存/现有存量」可能含空值/非数值 → 判定时容错，异常值跳过并记录，不整体失败。
