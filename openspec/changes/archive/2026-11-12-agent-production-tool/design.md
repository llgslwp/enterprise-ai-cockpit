# Design: query_production 生产完成率查询工具

## 目标

封装 `dashboard_calc`，让 agent 能回答排产复盘类问题：「本月/某月完成率多少」「哪些品类拖后腿」「各月完成率趋势」。

## 数据源与口径（复用已验证实现，不改逻辑）

- 数据源：`data/raw/成品生产计划.xlsx` 的「{N}月份成品计划」sheet（`dashboard_calc.resolve_plan_file()` 自动定位）。
- 字段语义（与排产链路 `fill_chengpin.py` 一致）：
  - **计划数** = 未完成数量（要生产的量）；
  - **完成数** = 当月实际完成（动态）；
  - **完成率** = 完成数 ÷ 计划数 × 100%，**超 100% 保持真实值（超产，非错误）**。
- 维度：
  - **4 区段**（计划的来源分类）= 历史 / 当月库存 / 当月订单 / 世达；
  - **6 品类** = 加力钳 / 美式 / 含钛 / 内管钳 / 钻杆钳 / 套管钳。

## 接口设计

`query_production(month: int = 0) -> str`（返回 JSON 字符串）

- `month = 0`（默认，用户未指定月份）→ 返回**最新月详情 + 各月完成率概览**（趋势）；
- `month = 1~12`（用户指定）→ 返回**指定单月详情**。

`month` 语义与 `query_stock` 一致（绝对月份，1-12；0=当前/最新月），系统提示词已注入「本月=11、上月=10」，模型照抄数字即可。

```json
    "9": {"计划数": 1, "完成数": 1, "完成率": 1},

```

- 字段名用中文带明确语义（「计划数/完成数/完成率」），避免裸 `plan/done/rate` 让模型猜；
- 「各月完成率」= 各月总体（全部品类合计）完成率；「各月品类完成率」= 各月按 6 品类拆分的完成率（支持「某品类逐月趋势」）。两者仅在 `month=0` 时返回（趋势用途）；指定单月时不返回。
- 完成率保留 1 位小数（数据层 `round(d/p*100, 1)` 已处理），整数率去掉小数点。

## 关键设计决策

1. **复用而非重写**：直接调 `dashboard_calc.calc_month` / `build_dashboard`，不复制任何计算逻辑，保证与前端大屏 `/dashboard` 接口同源同值。
2. **字段自带语义**：沿用 `query_gap` 的方向标注经验——字段名直接点明含义，把「完成率可能 >100% 是超产不是错」写进 docstring，不给模型留「误判超 100% 为异常」的机会。
3. **完成率低 = 拖后腿**：docstring 明确「完成率越低进度越慢」，模型据此回答「哪些品类拖后腿」，无需自行判断方向。

## 性能

`build_dashboard` 实测 169ms（zip 直读一次读全部月份），符合全局 NFR（常规查询 ≤200ms）。

## 风险与对策

- **风险**：模型可能混淆「完成率」与「缺口」两个概念（一个查进度、一个查差额）。**对策**：docstring 明确各自「使用时机」——「进度/完成率/完成得怎么样」→ query_production；「还差多少/缺口/缺料」→ query_gap。
