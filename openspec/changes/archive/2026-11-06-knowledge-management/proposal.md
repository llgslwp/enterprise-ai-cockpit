# Proposal

## Why

企业AI驾驶舱规划的企业知识库（RAG 检索问答）需要一个「文件入口」：业务方把生产工艺、公司制度、行业知识等文档上传进系统，供后续检索问答使用。目前系统没有文件上传与管理能力，知识库内容无处落地。本次新增「知识管理」模块，作为知识库的**文件管理端**，先解决「文件怎么进来、怎么管」，RAG 索引与问答后续单独接。

## What Changes

- **新增「知识管理」模块**（前端菜单 + 页面 + 后端接口），单页承载「上传区 + 文件列表管理」。
- **文件上传**：支持拖入或点击选择，文件类型限定 MD、TXT、docx、PDF 四类（入库前校验扩展名）。
- **入库类型**：每个文件标注入库类型——工艺类 / 制度类 / 知识类（三选一）。
- **版本管理**：保留历史版本文件，支持查看版本历史、下载任意历史版本、回滚（复制历史版本为新的当前版本，版本链完整可追溯）。
- **文件启停**：现有文件查看列表，支持停用 / 启用（停用不删除，保留在磁盘与列表）。
- **可见范围**：每个文件记录可见范围标签（先做标签预留，本阶段不拦截访问）。
- **存储**：文件与元数据存本地 `data/knowledge/`（文件按文档分目录 + 一份元数据索引 JSON）。

## 用户已拍板的关键决策（2026-11-06）

1. 可见范围 = **先做标签预留**（非真实权限拦截）。
2. 与 RAG 关系 = **知识库文件管理端**，本模块只做文件管理，索引/问答单独接。
3. 版本管理 = **保留历史版本文件**。
4. 存储 = **本地 data 目录**。

## Capabilities

### New Capabilities
- `knowledge-management`: 知识管理（文件上传、类型标注、可见范围标签、版本管理、启停、本地存储）。

### Modified Capabilities
- `system-platform`: ①「模块承载边界」requirement 将「知识库（知识管理）」纳入本次范围（「多用户登录」仍不在范围）；②「知识库纳入架构」requirement 由「本期不建设内容、仅预留」改为「本期落地文件管理，RAG 检索问答后续分期」。

## Impact

- **前端**：`web/src/views/Home.vue` 新增「知识管理」模块菜单；新增 `KnowledgeManage.vue` 页面（上传区 + 文件列表 + 版本弹层）；`router/index.js` 注册路由；`api/index.js` 新增知识管理接口。
- **后端**：新建 `modules/knowledge/`（路由 + 存储 + 版本管理），挂入 FastAPI。
- **数据**：新建 `data/knowledge/` 目录（元数据索引 + 分文档版本目录）。
- **依赖**：无新增第三方依赖（文件存储用原生文件系统，元数据用 JSON）。
