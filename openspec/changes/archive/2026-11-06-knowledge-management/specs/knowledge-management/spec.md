# Spec Delta

## ADDED Requirements

### Requirement: 文件上传与类型校验
系统 SHALL 支持通过拖入或点击选择上传 MD、TXT、docx、PDF 四类文件，并在入库前校验文件扩展名。

#### Scenario: 上传合法类型
- **WHEN** 用户拖入或点击选择 `.md`/`.txt`/`.docx`/`.pdf` 文件
- **THEN** 系统 MUST 接收该文件并入库

#### Scenario: 拒绝非法类型
- **WHEN** 用户选择四类之外的文件（如 `.jpg`/`.xlsx`）
- **THEN** 系统 MUST 拒绝并提示不支持的文件类型，不入库

### Requirement: 入库类型标注
系统 SHALL 要求每个入库文件标注入库类型（工艺类 / 制度类 / 知识类三选一），作为文件的分类元数据。

#### Scenario: 上传时选择入库类型
- **WHEN** 用户上传文件
- **THEN** 系统 MUST 要求用户从工艺类 / 制度类 / 知识类中选择一项，并随文件一并记录

### Requirement: 可见范围标签
系统 SHALL 为每个文件记录可见范围标签；本阶段标签仅作元数据预留，不做访问拦截。

#### Scenario: 上传时记录可见范围
- **WHEN** 用户上传文件
- **THEN** 文件 MUST 带有可见范围标签（默认「全员」，可修改）

#### Scenario: 标签不拦截访问
- **WHEN** 当前单账号用户查看文件列表或下载文件
- **THEN** 系统 SHALL 仅展示可见范围标签，不依据标签拦截访问

### Requirement: 版本管理
系统 SHALL 为每个文件保留历史版本，支持查看版本历史、下载任意历史版本、回滚。

#### Scenario: 上传新版本保留旧版本
- **WHEN** 用户为已有文件上传新版本
- **THEN** 系统 MUST 保留旧版本文件实体，新版本成为当前版本，版本号递增

#### Scenario: 查看版本历史
- **WHEN** 用户查看某文件的版本历史
- **THEN** 系统 MUST 列出其所有历史版本（版本号 / 上传时间 / 大小）

#### Scenario: 下载历史版本
- **WHEN** 用户选择某历史版本
- **THEN** 系统 MUST 允许下载该版本文件

#### Scenario: 回滚到历史版本
- **WHEN** 用户将某历史版本设为当前
- **THEN** 系统 MUST 复制该历史版本为新的当前版本（版本链单调递增、不重写历史），并更新当前版本指针

### Requirement: 文件列表与启停
系统 SHALL 提供文件列表查看，并支持停用 / 启用文件。

#### Scenario: 查看文件列表
- **WHEN** 用户进入知识管理模块
- **THEN** 系统 MUST 列出所有文件及其元数据（名称 / 入库类型 / 可见范围 / 版本 / 状态 / 更新时间）

#### Scenario: 停用文件
- **WHEN** 用户停用某文件
- **THEN** 系统 MUST 将该文件标记为停用，文件实体保留在磁盘与列表中（置灰标记）

#### Scenario: 启用文件
- **WHEN** 用户启用某停用文件
- **THEN** 系统 MUST 将其恢复为启用状态

### Requirement: 本地文件存储
系统 SHALL 将文件与元数据存储于本地 `data/knowledge/` 目录：文件按「入库类型 → 文档」两级目录保存各版本，元数据汇总于索引文件。

#### Scenario: 文件落盘与元数据写入
- **WHEN** 文件入库或新增版本
- **THEN** 系统 MUST 将文件实体写入 `data/knowledge/<入库类型>/<file_id>/` 目录，并将元数据写入索引文件

#### Scenario: 重启后可读取
- **WHEN** 系统重启
- **THEN** 元数据与文件 MUST 仍可从本地目录读取，不丢失
