# Proposal

## Why

2026-11-06 用户再次报「又提示登录失败，不是都改好了吗」。排查确认：这不是 login-stability（2026-11-05）已固化的三层根因（cookie 域 / 后端双进程 / 前端错误字段）复现，而是**第四层根因——启动时序**：

`start.ps1` 第 3 步「等待服务就绪」只 `Start-Sleep 6` 秒，且只检查前端 5173 返回 200，**从不检查后端 8000 是否就绪**。而后端 `main.py` 首次加载依赖（openpyxl / quality / knowledge 模块）要 10~20 秒才绑定 8000 端口，远大于 6 秒等待。于是每次重启：浏览器打开过早 → 用户手快登录 → vite 转发到 8000 时后端未绑端口 → 连接被拒 → 前端误报「登录失败，请检查账号密码」。

进程时间戳实测还原：后端 8:10:51 创建、前端 8:10:52 创建、6 秒后开浏览器、用户约 8:11:00 登录、后端 8:11:05~15 才就绪，完全吻合。

## What Changes

- **固化启动就绪等待约束**：`start.ps1` MUST 轮询等待后端 8000 端口 LISTEN 后再打开浏览器，消除「浏览器早于后端就绪」的登录失败空窗。

## Capabilities

### New Capabilities
（无）

### Modified Capabilities
- `system-platform`: 新增「启动就绪等待」约束。

## Impact

- **启动脚本**：`start.ps1`（第 3 步由「固定等 6 秒 + 只查前端」改为「先轮询等后端 8000 就绪 → 再等前端 200 → 才开浏览器」）。
- **依赖**：无新增第三方依赖。
