# Design

## Context

现有「库存管理」模块聚焦成品库存，预警只针对成品台账。本轮改造把它升级为「供应链管理」，纳入原料（毛坯）预警，形成「成品 + 原料」两条线。毛坯库（`261026/261031毛坯库.xlsx`）本就是「库存汇总看板」的五类 ERP 数据源之一，因此原料预警复用现有数据读取链路，仅新增「安全底线判定」这一环。

## Goals / Non-Goals

**Goals:**
- 改名语义升级：库存管理 → 供应链管理，子模块名对齐内容（成品总览/成品占比/重点成品）。
- 预警拆分：菜单上「库存预警」保留为父级，下挂「成品预警」（沿用现有逻辑）+「原料预警」（毛坯存量低于原料底线）两个子项。
- 重点成品页：标题由「重点关注规格明细」改为「重点成品」，明细数据字号加大 2 号。

**Non-Goals:**
- 不改路由 `/inventory/*` 与后端 `/api/inventory/*` 路径（仅显示名）。
- 不做原料的「消耗量/动态消耗」预警（毛坯库无消耗记录，数据不全）。
- 不引入采购/供应商等更广的供应链能力（本轮仅改名 + 原料预警）。

## Decisions

- **原料预警规则**：与成品预警同构——「现有存量 < 安全底线」即预警。底线值来自新建的「原料库存底线配置表」（开口式，空框架，用户后续填）。
- **数据源与结存口径**：最新毛坯库文件（按文件名日期取最新），结存取「现有存量」字段。
- **预警粒度**：货品名称 + 货品规格逐项（精确到每个毛坯件）。
- **配置表设计**：复用 `thresholds.py` 的开口式模式——配置表是数据而非代码，每次调用重新读取，缺表/空值静默跳过。
- **改名范围**：仅前端菜单 label 与页面标题，路由与后端接口路径保持不变（改动小、风险低，且 `/inventory` 前缀在语义上仍可接受）。

## Risks / Trade-offs

- [原料底线值暂空] → 空框架阶段原料预警返回空（无预警项），符合预期；待用户填入底线值后生效。
- [毛坯库多快照] → 按文件名日期取最新，需保证 `data/raw/` 下毛坯库文件命名含日期且最新版在位。
