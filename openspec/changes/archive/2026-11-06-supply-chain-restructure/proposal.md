# Proposal

## Why

用户启动新一轮改造：把「库存管理」模块升级为「供应链管理」，体现系统从「成品库存」扩展到「成品 + 原料」两条线。具体两点：

1. **模块与子模块改名**（语义升级）：库存管理 → 供应链管理；库存总览 → 成品总览；库存占比 → 成品占比；库存明细 → 重点成品（页面标题由「重点关注规格明细」改为「重点成品」，且明细数据字号加大 2 号）。
2. **预警拆分 + 新增原料预警**：原「库存预警」只针对成品（成品台账「年末库存」低于库存底线）。现改为「库存预警」保留为父级菜单，下挂「成品预警 + 原料预警」两个子项：成品预警承接现有成品数据不变；原料预警为新增能力，对「毛坯库」数据做安全底线预警。

## What Changes

- **改名（仅显示名，路由与接口不动）**：模块「库存管理」→「供应链管理」；子模块「库存总览/库存占比/库存明细」→「成品总览/成品占比/重点成品」。前端菜单 label 与页面标题同步改；路由 `/inventory/*` 与后端 `/api/inventory/*` 保持不变。
- **预警菜单结构**：「库存预警」保留为父级菜单，下挂「成品预警」「原料预警」两个子项（三级菜单）。「成品预警」承接原库存预警的成品数据与逻辑不变。
- **新增「原料预警」**：数据源为 `data/raw/` 最新毛坯库文件（字段：货品名称/货品规格/现有存量/批号）；判定规则为「现有存量 < 原料库存底线」；底线值来自新建的「原料库存底线配置表」（开口式，空框架，用户后续自行维护）；预警粒度为「货品名称 + 规格」逐项。

## Capabilities

### New Capabilities
（无 —— 原料预警归入既有 `inventory-status` 能力，属该能力的扩展）

### Modified Capabilities
- `inventory-status`: ①「库存预警」requirement 正文澄清其前端显示名为「成品预警」（行为不变，改名归前端层）；②新增「原料预警」requirement。

## Impact

- **前端**：`web/src/views/Home.vue`（菜单改名 + 拆项）；`InventoryOverview.vue` / `InventoryShare.vue` / `InventoryDetail.vue` / `InventoryGap.vue`（页面标题改名）；新增「原料预警」页面与路由注册。
- **后端**：`modules/inventory/` 新增原料预警接口 + 原料底线配置表读取模块（复用 `thresholds.py` 的开口式设计）。
- **数据**：新建 `data/raw/原料库存底线配置表.xlsx`（空框架）。
- **依赖**：无新增第三方依赖。
