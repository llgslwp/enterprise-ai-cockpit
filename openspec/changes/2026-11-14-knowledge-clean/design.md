# 设计说明：文本清洗环节

## 方案选型

| 方案 | 优点 | 缺点 | 取舍 |
|---|---|---|---|
| A. 清洗放解析器内部（load_docx/load_pdf 里顺手洗） | 改动集中 | 耦合解析与清洗，难以对「已解析文本」统一清洗；难加评测对比 | 否 |
| B. 独立 cleaner 环节，解析后 / 分块前统一洗 | 职责单一、可评测对比、可独立演进 | 多一层调用 | **采用** |

选 B：清洗是「解析 → 分块」之间的独立变换，独立成模块后能对「清洗前 / 清洗后」做切片统计对比（验收标准 1），也便于二期往 `clean_text` 里加 PDF/Word 专项而不动解析器。

## 一期清洗项（通用，全类型）

| 类别 | 清洗项 | 实现 |
|---|---|---|
| 通用 | 不可见 / 控制字符清理 | 删除 `\x00-\x08 \x0b \x0c \x0e-\x1f \x7f` 及 C1 区 `\u0080-\u009f`、替换符 `\ufffd`（OCR 重灾） |
| 通用 | 换行符统一 | `\r\n` / `\r` → `\n` |
| 通用 | 全/半角空格与制表符统一 | 全角空格 `\u3000` → 半角 `\u0020`，`\t` → 空格，行内连续空格折叠为 1 个 |
| 通用 | 连续空行折叠 | `\n{3,}` → `\n\n`（保留段落边界，去除多余空行） |
| 通用 | 首尾空白 | `strip()` |
| 通用 | 重复段落去重 | 按「规范化内容指纹」去重，保留首次出现段落 |

## 分块后过滤去重

| 类别 | 处理 | 实现 |
|---|---|---|
| 过短切片 | 过滤 `len < min_len`（默认 30 字） | 丢弃纯标题孤立切片 |
| 重复切片 | 按「title_path + 规范化内容指纹」去重 | 防 Word 重复表头 / 正文表格重复 |

### 阈值 N=30 的依据（实测 177 切片）

- `<30` 字共 7 个，全部是**纯标题孤立切片**（8~27 字：`离职交接管理办法`、`## 机加工工段`、`## 1.3 月度趋势分析`、`# 附录…\n## 装配工段` 等），无正文、无独立检索价值，标题语义已由相邻切片的 `title_path` 元数据承载。
- `>=30` 字起都是「标题 + 正文」有效切片（最短 37 字：`## 7.3运输与贮存 \n产品运输与贮存按GB/T 5305的规定执行。`）。
- 故 `min_len=30` 可滤掉 7 个碎屑、不误伤任何有效切片。

## 二期专项（暂不实现，等素材真入库）

- **PDF 断行合并**：识别标题行与正文行的换行差异，把 PDF `extract_text` 造成的错误断行合并回完整句，同时保留标题边界（勿把标题与正文拼成一段）。
- **PDF 去页眉页脚 / 页码 / 分页符**。
- **Word 表格结构化**：辨表头 / 数据行、识别合并单元格、空表跳过。

## 数据流

```
load_all() → [Document...]
   ↓ clean_documents()          # 分块前通用清洗（纯内存，不回写文件）
   ↓ chunk_all()                 # 语义分块
   ↓ filter_chunks()             # 分块后过滤碎屑 + 去重
   ↓ build_index()               # 向量化 + BM25
```

清洗只作用于内存中的 `Document.page_content`，不触碰 `data/knowledge/` 下任何原始文件，天然不违反数据源三铁律。
