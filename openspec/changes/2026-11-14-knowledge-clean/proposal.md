# 知识库入库「文本清洗」环节补建

## Why

RAG 入库链路「解析 → 分块 → 索引」之间缺少「清洗」环节，脏切片直接进索引、稀释检索质量。已观测到的脏源：

1. `load_docx` 表格 `" | ".join` 无脑拍平，不辨表头 / 合并单元格 → 半截表切片；
2. `load_pdf` `extract_text` 断行错乱、夹分页符（知识类 QB_T2508 全文件仅切 2 片）；
3. 分块后碎屑：实测最小切片 8 字（纯标题孤立成片，如「离职交接管理办法」「## 机加工工段」）；
4. Word 重复表头 / 正文表格重复 → 语义重复切片。

当前 17 文档 / 177 切片素材较干净（实测 7 个 <30 字纯标题碎屑、0 重复），可暂缓；但任一触发条件（OCR 扫描 PDF 入库、表格文件增多、文档上量、评测检索不达标）出现后即必须补清洗。

## What Changes

新建 `modules/knowledge/cleaner.py`，在 `load_all()` 之后、`chunk_all()` 之前调用 `clean_documents()`（分块前清洗），并在 `chunk_all()` 之后调用 `filter_chunks()`（分块后过滤去重）。

一期只落「通用清洗 + 分块后过滤去重」（成本低、收益稳）；PDF 断行合并 / Word 表格结构化等专项等对应素材真入库再补，不对未入库的 OCR 提前空写。

## Impact

- 能力：knowledge-base（新增「文本清洗」requirement）
- 不改任何 API 契约、不回写原文件、不碰数据源三铁律（只读当前版本 / 跳过停用 / 排除 index/）
- 清洗为纯内存文本变换，离线建索引阶段执行
