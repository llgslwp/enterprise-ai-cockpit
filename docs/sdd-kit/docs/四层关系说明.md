# SDD 开发套件 · 四层关系说明

本套件让「规范驱动开发（Spec-Driven Development）」可在任意一台电脑上复现。它由**四层**组成，其中只有两层是你自建、需随包分发的，另外两层是官方产物、需在目标机器上安装生成。

## 四层关系图（谁调谁）

```
┌─ ① 开发铁律（内容方法论 · 自建，随包分发）─────────────┐
│  skills/openspec/SKILL.md 尾部引用 + docs/开发协作铁律.md │
│  管「怎么做才对」：选型提审 / 需求必问 / 反例回归 / 实跑  │
└──────────────┬─────────────────────────────────────┘
               │ 指导「怎么做才对」↓
┌─ ② 路由 skill（接线层 · 自建，随包分发）────────────────┐
│  skills/openspec/SKILL.md（主文件）                    │
│  管「定位并加载官方指令」，本身几乎不含流程细节          │
└──────────────┬─────────────────────────────────────┘
               │ 定位并加载 ↓
┌─ ③ OpenSpec 官方 skill（流程指令 · 官方，目标机 init 生成）┐
│  .agents/skills/openspec-{propose,apply,archive,update,  │
│  sync,explore}/SKILL.md                                │
│  管「流程边界」：何时能写码 / 何时归档 / 何时只思考      │
└──────────────┬─────────────────────────────────────┘
               │ 调用 ↓
┌─ ④ OpenSpec CLI 本体（真正执行 · 官方，npm 全局安装）─────┐
│  openspec list / validate / archive / context 等命令     │
│  skill 只是指令，最终由 CLI 程序落盘、校验、归档          │
└────────────────────────────────────────────────────────┘
```

## 分层职责速览

| 层 | 名称 | 管什么 | 谁提供 | 随包分发? |
|---|---|---|---|---|
| ① | 开发铁律 | 内容方法论（怎么做才对） | 你（复盘沉淀） | ✅ 是 |
| ② | 路由 skill | 定位并加载官方指令 | 你（搭建） | ✅ 是 |
| ③ | OpenSpec 官方 skill | 流程边界（何时做什么） | OpenSpec 官方 | ❌ 目标机 init 生成 |
| ④ | OpenSpec CLI | 真正执行（落盘/校验/归档） | OpenSpec 官方 | ❌ npm 全局安装 |

## 关键认知

- **①和②是你自建的**，跨机器通用，所以能打包进套件。
- **③和④是官方产物**，不能也不该随包分发：③由 `openspec init --tools agents` 在目标机器自动生成，④由 `npm i -g` 全局安装。这正是「插件 + 依赖声明」的标准形态——就像 npm 包本身不含 node 一样。
- **①与③是分层关系，不冲突**：一个管「如何对」，一个管「何时停」，叠加执行。
- 铁律①（需求必问）是 OpenSpec 官方「material ambiguity 必问」的**判定标准细化**，非平行新规。
