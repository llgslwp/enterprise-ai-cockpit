# 人机交互蓝图

> 本文档定义「企业 AI 驾驶舱」的人机交互全景设计：四个角色的端口界面、全局智能助手（Agent）的对话形态、自然语言到操作的完整流程、反馈确认机制与分期实现路线。
>
> 定位：本文档是**交互设计的权威蓝图**，后续所有界面前端实现与 Agent 对话逻辑都以它为基准。它同时是本项目作为「制造业 × Agent」案例在 GitHub 上体现「产品思维 + 架构能力」的核心成果之一。

---

## 一、交互设计原则

1. **对话为主，按钮为辅**：核心操作（上传、写回、排产、查汇总）以自然语言对话驱动，传统按钮/表单作为辅助与兜底。
2. **全局智能助手**：一个全局可唤起的对话助手，能理解上下文并触发任意角色职责内的操作，不绑定特定页面。
3. **透明可追溯**：所有由 Agent 触发的操作，必须让用户看清「系统理解成了什么、准备做什么、结果是什么」，拒绝黑箱。
4. **确认关键操作**：涉及写回、排产等**有副作用**的操作，执行前必须确认；查询类操作直接返回。

## 二、四角色端口 + 全局助手总览

| 角色 | 端口核心交互 | 输入方式 | 主要输出 | 是否有副作用操作 |
|:---|:---|:---|:---|:---|
| 保管员 | 上传 ERP 库存文件、看文件状态 | 拖拽/选择上传 + 对话 | 上传成功/失败、文件清单 | 是（写文件）|
| 生产副总 | 看文件齐没齐、触发写回/排产 | 对话为主 + 按钮 | 操作结果、排产数据 | 是（写回/排产）|
| 总经理 | 看数据汇总看板 | 只看（对话可查询）| KPI 图表、趋势 | 否 |
| 质检员 | 看质量数据分析 | 只看（对话可查询）| 质量分析图表、根因 | 否 |

**全局智能助手**：四个角色各自端口内都有一个可唤起的对话助手，但助手的**权限与可执行操作**受当前登录角色约束。助手在「当前角色职责范围内」理解并触发操作。

## 三、全局智能助手（Agent）对话形态

### 3.1 助手定位

- 一个**常驻侧边栏/浮窗**，用户随时唤起。
- 助手知道**当前是谁在问**（角色）、**当前数据状态**（哪些文件已上传、哪个月份）。
- 助手只能执行**当前角色被允许**的操作（权限收敛）。

### 3.2 对话交互的基本形态

助手以「意图识别 + 参数补齐 + 确认 + 执行 + 反馈」五步闭环工作：

```
用户说一句话
   → ① 意图识别：这句话要干什么？（写回 / 排产 / 查库存 / 查汇总）
   → ② 参数补齐：缺什么信息？（哪个文件？哪个月份？）
   → ③ 确认（仅副作用操作）：系统复述「我理解你要…，对吗？」
   → ④ 执行：触发既有计算链路
   → ⑤ 反馈：结果摘要 + 可下载文件 / 图表
```

### 3.3 对话示例（贯穿核心闭环）

**场景：生产副总触发写回**

```
用户：「文件齐了，开始写回」
助手：「检测到 10 月份 6 份库存文件已全部上传。
       即将把成品台账入库记录写回到 10 月生产计划『当月实际完成』列，
       确认执行吗？」            ← 意图识别 + 参数补齐 + 确认
用户：「确认」
助手：「写回已完成：共匹配 176 个品类，写回 1234 条入库记录。
       结果文件：10月生产计划_回填.xlsx [下载]」   ← 执行 + 反馈
```

**场景：总经理查汇总**

```
用户：「这个月管钳的产量和库存怎么样？」
助手：「10 月管钳产量 3.2 万把（环比 +8%），
       当前库存周转天数 18 天。
       [查看看板]」             ← 查询类，无需确认，直接返回 + 图表入口
```

## 四、自然语言 → 操作 的完整流程

### 4.1 意图分类（本期最小集）

| 意图 | 触发链路 | 是否副作用 | 需确认 |
|:---|:---|:---|:---|
| 上传文件 | 触发上传入口 | 是 | 否（用户已主动选文件）|
| 写回 | 回填链路 | 是 | **是** |
| 排产 | 半成品排产链路 | 是 | **是** |
| 查库存/台账/汇总/质量 | 查询接口 | 否 | 否 |

### 4.2 参数补齐策略

当用户指令缺少必要参数（如「写回」没说哪个月），助手用**当前上下文默认 + 追问**补全：
- 有唯一默认（如当前月）→ 复述默认值并确认。
- 有多个可能 → 列出选项追问（如「写回 9 月还是 10 月？」）。

### 4.3 反馈与错误处理

- **成功**：一句话结果摘要 + 关键数字 + 可下载文件/图表入口。
- **部分成功**：说明完成多少、跳过多少、为什么（可追溯）。
- **失败**：说明失败原因 + 建议下一步（不静默失败）。
- **无法识别**：明确提示「我没有理解，您是否要…」并列出最可能的 2-3 个候选操作。

## 五、四角色端口界面（每个端口长什么样）

### 5.1 保管员端口

- **主界面**：文件上传区（拖拽 + 选择），上传后显示文件清单与状态（已上传/待上传/缺失）。
- **助手交互**：「帮我看看还差哪些文件」「这个月的库存文件齐了吗」→ 助手核对并提示缺失项。

### 5.2 生产副总端口

- **主界面**：文件上传状态总览（6 份源文件到齐情况）+ 操作触发区。
- **助手交互**：核心操作入口——「文件齐了，开始写回」「重新跑排产」。

### 5.3 总经理端口

- **主界面**：数据汇总看板（KPI 卡片 + 趋势图表，ECharts 消费 JSON）。
- **助手交互**：自然语言查询——「这个月产量」「各品类库存占比」。

### 5.4 质检员端口

- **主界面**：质量数据分析看板（质量指标、问题分布、根因分析图表）。
- **助手交互**：自然语言查询——「这个月质量问题集中在哪道工序」。（具体职责待启用该角色时细化，见 Open Questions）

| 三期 | 知识库（RAG）接入助手，支持工艺/作业指导书问答 | 规划中 |
